# SNUVT Physical — 배포·운영 안내

서울대 배구부 피지컬 트레이닝 보드를 내 주소로 운영하기 위한 안내서예요. 화면은 정적 파일(HTML·JS)이고, 로그인과 데이터 저장은 Supabase가 맡아요. 배포는 Vercel로 해요. 코딩 없이 따라 할 수 있게 순서대로 적었어요. 전체 30–40분 정도 걸려요.

> **진행 상황 (10/22)**: 1단계(데이터베이스 준비)와 2단계(config.js)는 Supabase 연결을 통해 이미 끝났어요. 3단계 GitHub 업로드부터 하면 돼요.

## 들어 있는 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 틀과 디자인 |
| `app.js` | 화면 동작 (로그인, 홈, 처방, 기록, 등록·측정, 훈련 부하) |
| `program.js` | 처방 엔진. ‘운동 처방 라이브러리’ 문서의 주차×요일 처방, 포지션·근력·균형 규칙, 부위별 통증 단계 재활이 여기 있어요 |
| `config.js` | Supabase 주소와 공개 키를 넣는 곳 (2단계에서 수정) |
| `supabase/remove_member.sql` | 관리자가 팀원 계정을 삭제하는 기능 (SQL Editor에서 한 번 실행) |
| `logo.png`, `logo-white.png`, `favicon.png` | 배구부 엠블럼 (밝은 화면용 남색, 어두운 화면용 흰색) |
| `supabase/schema.sql` | 데이터베이스 테이블, 권한 규칙, 주전 9명 초기 데이터 |

## 권한 구조

| 역할 | 볼 수 있는 것 | 할 수 있는 것 |
| --- | --- | --- |
| 승인 대기 | 아무것도 없음 | 가입만 함 |
| 선수 | **내** 홈·처방·통증 단계·측정·인바디·기록 | 내 이름으로 세션 기록·인바디 남기기 |
| 관리자 | 전부 | 선수 등록·수정, 부상 단계·측정·인바디 입력, 기록 삭제, 팀원 승인 |

이 규칙은 데이터베이스(RLS)에 걸려 있어서, 누가 화면 코드를 고쳐도 우회되지 않아요.

---

## 1단계. Supabase 프로젝트 만들고 데이터베이스 준비

1. https://supabase.com 에 가입하고 **New project**를 눌러요.
2. 이름은 `snuvt-physical`, 지역(Region)은 **Northeast Asia (Seoul)**을 골라요. 데이터베이스 비밀번호는 따로 적어 둬요.
3. 프로젝트가 만들어지면 왼쪽 메뉴 **SQL Editor → New query**를 열어요.
4. `supabase/schema.sql` 내용을 전부 붙여넣고 **Run**을 눌러요. "Success"가 나오면 끝이에요. 이 SQL은 한 번만 실행해요.
5. 왼쪽 **Table Editor**에서 `players` 테이블에 주전 9명이 들어 있는지 확인해요.

## 2단계. config.js 에 주소와 키 넣기

1. **Project Settings → API** (또는 Data API) 화면을 열어요.
2. **Project URL**과 **anon public** 키를 복사해서 `config.js`의 두 값에 붙여넣어요.
3. `service_role` 키는 절대 넣지 않아요. 그 키는 모든 권한 규칙을 무시해요.

## 3단계. GitHub에 올리기

1. https://github.com 에 가입하고 **New repository**를 만들어요. 이름은 `snuvt-physical`, Private으로 해도 돼요.
2. 저장소 화면의 **Add file → Upload files**에 `index.html`, `config.js`, `README.md`, `supabase` 폴더를 끌어다 놓고 **Commit changes**를 눌러요.

## 4단계. Vercel로 배포

1. https://vercel.com 에 GitHub 계정으로 로그인해요.
2. **Add New → Project**에서 방금 만든 저장소를 **Import**해요.
3. Framework Preset은 **Other**로 두고, 빌드 설정은 건드리지 않고 **Deploy**를 눌러요.
4. 1분쯤 지나면 `https://snuvt-physical-xxxx.vercel.app` 같은 주소가 생겨요. 이게 사이트 주소예요.

## 5단계. 로그인 주소 연결

1. Supabase로 돌아가 **Authentication → URL Configuration**을 열어요.
2. **Site URL**에 4단계의 사이트 주소를 넣고, **Redirect URLs**에도 같은 주소를 추가해요. 이걸 해야 가입 확인 메일의 링크가 우리 사이트로 돌아와요.
3. 이메일 인증은 쓰지 않아요. **Authentication → Sign In / Providers → Email**에서 *Confirm email*을 꺼 두면 가입 즉시 내 정보 입력으로 넘어가고, 관리자 승인으로 걸러요.

## 6단계. 내 계정을 관리자로 지정

1. 사이트에 들어가 **가입하기**로 내 이메일과 비밀번호를 등록하고, 확인 메일의 링크를 눌러요.
2. 이 시점엔 "승인을 기다리고 있어요" 화면이 나와요. 정상이에요.
3. Supabase **SQL Editor**에서 아래를 내 이메일로 바꿔 한 번 실행해요.

```sql
update public.profiles
  set role = 'coach', player_id = (select id from public.players where name = '최수혁')
  where email = '내-가입-이메일@example.com';
```

4. 사이트에서 **승인됐는지 다시 확인**을 누르면 관리자 화면이 열려요.

## 7단계. 팀원 초대

1. 팀원에게 사이트 주소를 보내 가입하게 해요.
2. 가입한 사람은 로그인하면 **내 정보 입력** 화면에서 이름, 포지션, 키·몸무게, 경력, 웨이트 경험, 부상·통증을 직접 입력하고 제출해요. 승인 전까지는 스스로 고칠 수 있어요.
3. 관리자는 **등록·측정 → 팀원 계정**에서 "승인 대기 · 정보 제출함" 계정의 역할을 **선수**로 바꾸고 **저장**해요. 선수 이름은 제출한 정보로 자동 연결돼 있어요.
4. 승인된 선수는 로그인하면 자기 처방이 먼저 보이고, 자기 이름으로 세션 RPE를 기록할 수 있어요. 승인 후 정보 수정은 관리자가 해요.

## 운영 메모

- **10/26 측정날**: 관리자 계정으로 **등록·측정**에서 선수별 기본 정보, 부상·통증(동의 체크 필수), 측정값을 입력하면 처방이 바로 바뀌어요.
- **통증 단계**: **등록·측정 → 통증 단계**에서 부위별로 1 높음(7점 이상·쉬어도 아픔) / 2 중간(4–6점) / 3 낮음(3점 이하·세게 할 때만) / 4 복귀(통증 없음) 중에 고르면 그 단계 재활 운동이 프로그램에 붙어요. 진행 규칙은 통증 모니터링 모델(운동 중 5 이하, 다음 날 아침 평소대로, 주마다 늘지 않기)을 따라요. 안 고르면 가입 때 낸 통증 점수로 임시 단계가 정해져요.
- **인바디**: 선수 본인 또는 관리자가 **기록** 탭에서 입력해요. 가장 최근 인바디 체중이 상대 근력(스쿼트 5RM ÷ 체중) 계산에 쓰여요. 체지방 순위나 감량 처방은 만들지 않아요.
- **고치고 싶을 때**: GitHub에서 파일을 수정해 Commit하면 Vercel이 1분 안에 자동으로 다시 배포해요.
- **다음 대회 블록**: Supabase **Table Editor → settings**에서 대회 이름, 블록 시작 월요일, 대회 날짜만 바꾸면 4주 트랙과 D-day가 그 대회 기준으로 바뀌어요.
- **개인정보**: 부상·통증은 민감한 정보예요. 가입·입력 전에 처방 목적으로만 쓴다는 동의를 받고, 꼭 필요한 항목만 넣어요. 졸업·탈퇴한 선수는 관리자 화면에서 삭제하면 측정·기록·부상 정보가 함께 지워져요.
- **비용**: 이 정도 규모는 Supabase·Vercel 무료 요금제 안에서 운영될 거예요. 정확한 한도는 각 서비스의 요금 안내에서 확인해 주세요.
