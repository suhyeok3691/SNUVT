# SNUVT — 서울대 배구부 관리

남자부·여자부가 같이 쓰는 배구부 앱이에요.

- 화면: 정적 파일(HTML·JS)
- 로그인·데이터: Supabase (프로젝트 `juhcaodotxspzzzfzrnt`)
- 배포: Vercel. [GitHub `suhyeok3691/SNUVT`](https://github.com/suhyeok3691/SNUVT)의 `main`에 올리면 자동으로 배포돼요.
- 주소: https://snuvt.vercel.app

이 문서 하나에 구조·데이터·운영을 모았어요. DB의 정확한 정의는 `supabase/schema.sql`에 있어요.

## 3. 팀과 직책

### 팀
- 가입할 때 남자부·여자부를 골라요. 다른 팀 데이터는 DB 규칙(RLS의 `team scope`)으로 막혀서 보이지도, 고쳐지지도 않아요.
- 팀마다 다른 것:
  - 정규 훈련 요일: 남자부는 1학기 월·목, 2학기 수·금이고 여자부는 반대예요. 시간은 18:00–21:00.
  - 네트 높이: 남자부 243cm, 여자부 224cm
  - 일정·공지·영상·훈련 계획
- 총관리자(`profiles.super`)는 설정에서 남자부·여자부를 오갈 수 있어요.
- 여자부 첫 관리자는 그 사람이 여자부로 가입한 뒤 SQL Editor에서 정해요:
  `update public.profiles set role = 'coach' where email = '이메일' and team_id = 'women';`
  그다음부터는 앱의 관리 → 부원에서 직책을 정하면 돼요.

### 직책 (팀마다)

| 직책 | 할 수 있는 것 | 서버 권한 `private.can(...)` |
| --- | --- | --- |
| 관리자 · 주장 | 전부 | (모두 true) |
| 부주장 | 일정 · 교류전 · 엔트리 · 공지 · 명단 · 영상 · 훈련 관리 | schedule · notice · roster · video · attend |
| 훈련 담당 | 훈련 계획 · 훈련 관리(정규 훈련 변경 · 자율 훈련 · 불참 확인) | practice · attend |
| 총무 | 공지 · 명단 | notice · roster |
| 피지컬 담당 | 피지컬 프로그램 편집 · 측정 수정 · 리포트 | training |
| 전력분석 담당 | 전력분석 경기 추가·수정, 모든 입력 고치기 | analysis |
| 영상 담당 | 영상 추가·수정 | video |
| 부원 · 군 복무 | 내 운동·기록 · 일정 · 참·불참 투표 · 불참 · 전력분석 입력 | — |

- 한 사람이 직책을 여러 개 맡을 수 있어요(`players.titles`, 예: 피지컬 + 영상). 권한은 맡은 직책을 모두 합친 것이고, 화면 보기는 '내 직책 ↔ 부원'이에요.
- 앱의 `STAFF_PERMS`(app.js)와 DB의 `private.can`은 항상 같게 맞춰요.
- 정규 훈련은 참석이 기본이라 '불참'만 누르고, 자율 훈련·대회·교류전은 참·불참 투표를 해요.

### 개인정보 규칙
- 부상·통증·컨디션·개인 조정은 본인과 관리자(관리자·주장)·피지컬 담당만 봐요.
- 키·몸무게(`player_private`)는 본인과 관리자·피지컬 담당만 봐요. 여자부는 몸무게 "비공개"를 고를 수 있음(가입 정보 · 내 정보): 고르면 몸무게를 아예 저장하지 않고 `player_private.weight_private = true`(RPC `set_weight_private`), 관리자 화면·엑셀엔 "비공개". 전화번호(`player_contacts`)는 본인과 명단 담당만 봐요.
- 체지방 순위나 감량 처방은 만들지 않아요.
- 졸업·탈퇴하면 개인정보를 지우고(`private.wipe_personal`), 이름과 운동 기록만 남겨요.

## 5. 서버 함수 · 예약 작업

| 서버 함수 | 누가 부름 | 하는 일 |
| --- | --- | --- |
| `push` | 예약 작업 · 공지 트리거 | 휴대폰 알림. 알림 키는 vault에 처음 한 번 만들어 둠 |
| `yt-latest` | 앱(로그인) | 팀 재생목록의 '마지막 업데이트' 날짜 → 최근 것을 위로 |
| `jp-sync` | 예약 작업 | 일본 고교 영상 모으기·태그 (mode `new` · `full` · `retag` · `fill` · `schools`) |
| `jp-block` | 예약 작업 | 지역 대회 결과 모으기 (koko-volley.com 지역 카테고리) |
| `jp-roster` | 예약 작업 | 하루코 출전 명단 모으기 (春高バレー.online 명단 페이지) |
| `jp-pref` | 예약 작업 | 현 대회 결과 모으기 (koko-volley.com 현별 글) |
| `jp-nat` | 예약 작업 | 전국대회 대진 모으기 (하루코·인터하이·국민스포츠대회) |
| `jp-search` | 앱(로그인) | 유튜브 검색 결과만 돌려줌 (저장 안 함) |

예약 작업 (pg_cron, 한국 시간):
- `push-hourly` 매시 정각: 사람마다 고른 시각에 아침 컨디션·저녁 기록 알림
- `jp-sync-new` 매일 05:00, `jp-sync-full` 매일 05:30, `jp-schools-daily` 매일 06:00, `jp-rank-daily` 매일 06:50(랭킹 다시 계산)
- 매주 화요일 새벽: `jp-nat-weekly` 04:00 → `jp-block-weekly` 04:10 → `jp-pref-weekly` 04:15 → `jp-roster-weekly` 04:20 → `jp-retag-weekly` 04:30 → `jp-fill-weekly` 04:45

예약 작업은 `private.*_call()` 함수가 vault의 `push_cron` 비밀값을 `x-cron` 헤더에 넣어 부르고, 서버 함수는 그 값이 맞을 때만 동작해요.

## 6. 일본 고교 영상

1. **모으기** (`jp-sync`): 등록한 채널·재생목록의 영상 목록을 유튜브 페이지에서 읽어요(API 키 없음). 2010년 이전 영상은 넣지 않아요.
2. **태그**: 제목에서 다음을 찾아 붙여요.
   - 학교: `jp_schools` 이름·별칭, `re:`로 시작하면 정규식
   - 대회: 해시태그보다 제목 본문을 먼저 보고, 여럿이면 먼저 나온 것
   - 연도: 20xx · 令和 · 平成 · 第N回 · 국민스포츠대회 개최지
   - 라운드 · 남녀
3. **위계**: 그해 전국 대진(`jp_matches`)에 두 팀이 있으면 전국 본선(대진의 라운드)으로 넣어요. 아니면 현 예선이에요. 국민스포츠대회의 블록 예선은 '블록 예선'으로 따로 넣어요.
   - 화면 순서: 결승 → 4강 → 3위전 → 8강 → 16강 → … → 현(블록) 예선
4. **대진** (`jp-nat`): 다음 사이트에서 모아요.
   - koko-volley.com: 하루코·인터하이
   - xn--8wv97xz6xo7h.online: 하루코 보충
   - zutto-sports.com: 국민스포츠대회
5. **빈 경기 채우기** (`fill`): 최근 7년 전국 결승·4강·3위전·8강 중 영상이 없는 경기를 유튜브에서 검색해 넣어요(출처 `search`).
   - 같은 대회·같은 해로 읽히고, 두 팀 이름이 다 있는 배구 영상만 넣어요.
   - 하이라이트·쇼츠·모음은 빼요. 길이를 알 수 있으면 8분 이상만 넣어요.
6. **학교별 찾기** (`schools`): 하루에 60개교씩, 검색한 지 오래된 학교부터 `현 학교 バレー 男子/女子`로 검색해 그 학교가 태그되는 8분 이상 경기 영상을 학교당 10개까지 넣어요.
7. **학교 목록**: 현 대회 4강 이상(`jp_pref_top`) + 전국 4강 이상 학교. 영상에서 학교를 만들지 않아요.
   - 새 학교는 `jp_pref_top`에서 사전에 없는 이름을 골라 `jp_schools`에 손으로 넣어요(한글 읽기 확인).
   - 한글 이름(`name_ko`)은 현지 발음으로: 읽기(`kana`)에서 장음은 빼요(崇徳 そうとく → 소토쿠, 九州 きゅうしゅう → 큐슈, 駿台 すんだい → 순다이, か·た행은 카·타). 만드는 규칙은 `supabase/k2h.py`. 예전 이름은 `name_ko_old`에 남겨 검색에도 써요.
   - 화면: 랭킹(20위, 더 보기 100위) → 지역 → 현 → 학교(랭킹 순), 위 검색창으로 바로 찾기

## 6-0. 실시간 경기 분석 (`live.js`, Tactic 버튼판 방식)
- 대회 탭 순서: 대회 · 교류전 · 전력분석 · 교내 대회

- 분석 팀은 SNU가 아니어도 됨: 경기 추가 창의 "분석 팀"(비우거나 SNU면 SNU = 명단 선수로 고름) · "상대 팀". 다른 팀이면 두 팀 다 등번호로 기록(`opp_no`에 번호, `side` us = 분석 팀). "명단 · 로테" 창(팀마다): 명단(번호 + 포지션 OH·OP·MB·S·L, 마지막 빈 줄에 쓰면 빈 줄이 저절로 생김, 줄마다 ✕) → "자동 배치"(1 S 서브 · 2 OH · 3 MB · 4 OP · 5 OH · 6 MB, 리베로 빼고 명단 순서대로) → "OH 바꾸기" · "MB 바꾸기" · "↻"(한 칸 로테 방향, S가 1→6→5→4…) · "↺"(반대), 칸 번호는 직접 고쳐도 됨. 칸마다 포지션 표시, 위에 "S n번 자리 · Rn"(S 1번 = R1, 6 = R2, 5 = R3, 4 = R4, 3 = R5, 2 = R6). 세트 처음(기록 없음)에 저장하면 그 팀 로테 번호도 S 자리로 맞춤. SNU는 칸마다 선수 고르기. 리베로 칸(명단에 L이 있으면 저절로, SNU는 엔트리의 L 선수) → 배구 규칙대로 자동 교대: MB가 뒷줄(5·6, 서브권이 없을 때는 1도)에 오면 리베로가 섬, MB가 1번에서 서브할 때는 MB 그대로, 서브권을 잃으면 리베로가 들어오고 MB가 앞줄(4)로 올라가면 다시 MB. 번호판에 리베로는 청록색 → 명단은 `live_games.roster`, 코트는 세트별 `sets[n].lu[side] = {rot, slots}`(넣을 때 로테 기준). 코트를 넣으면 번호판이 코트 모양(자리 번호 표시)으로 바뀌고 로테가 돌면 선수도 같이 돎, 나머지는 아래 작게. 공격 기본값은 포지션으로. 기록이 있으면 SNU ↔ 다른 팀은 못 바꿈
- 번호로 기록하는 팀은 등번호 대신 이름표도 됨(OH1 · OH2 · MB1 · MB2 · OP · S · Li, 교체는 OH3 · Li2 · S2 …, 포지션은 이름표로 저절로) → 기록은 `live_rallies.tag`. 명단 창에 "+ OH" · "+ MB" · "+ OP" · "+ S" · "+ Li"(다음 이름표를 붙여 줄 추가)
- 교류전: 상대는 명단을 안 넣으면 이름표 기본 명단 + 기본 배치(1 S · 2 OH1 · 3 MB1 · 4 OP · 5 OH2 · 6 MB2, 리베로 Li). SNU는 저장한 코트가 없으면(대회·교류전·전력분석 모두) 명단 포지션으로 6명을 자동 배치: 후보 순서 그 세트 출전(교류전) → 주전 → 엔트리 → 나머지 부원, 리베로는 후보 중 첫 L. 명단 창의 "자동 배치"도 SNU는 칸이 비어 있으면 같은 순서로 골라 채움

  - 세트: 리시브와 공격 사이 따로 한 줄(`kind = 'set'`, 3·2·1·범실). 세터(S)가 올리면 메이킹, 다른 포지션이면 이단, 바로 앞 리시브·디그·캐치가 1이면 세터가 올려도 이단(`two`). 결과에 팀마다 "세트" 표(메이킹 · 이단 · 사람별 세트 수 · 점수 · 범실 · 바로 다음 공격 득점% · 효율). 예전 공격 기록의 `setter` · `set_q`도 같이 셈
  - 공격 범실을 누르면 공격 미스(1) / 토스 미스(2) 고르기
  - 서브 들어감을 누르면 점수 3 좋음 · 2 보통 · 1 약함(컴퓨터 3·2·1) 고르기, "점수 없이"(0)도 됨 → res s3·s2·s1·in
  - 공격 득점(두 팀)을 누르면 코트 창: 공격 종류 · 타법을 고르고 지키는 쪽 코트를 SNU 쪽에서 본 그림(상대 공격 = 우리 코트, 네트가 위 · 우리 공격 = 상대 코트, 네트가 아래로 180° 돌림. 구역 선만 있고 번호 표시 없음. 저장은 지키는 팀 기준 9구역: 앞 4·3·2 / 가운데 7·8·9 / 뒤 5·6·1)에서 떨어진 자리를 누르면 저장(x·y 0~100 + 구역). 컴퓨터는 숫자 1~9 = 그 구역, 0 = 코스 모름
  - 버튼 색은 옅은 바탕 + 진한 글자(득점 초록 · 범실 빨강)
  - 점수 상황(리드 · 동점 · 추격)은 점수로 저절로 붙음
  - 컴퓨터: 위 단축키, 숫자 = 선수 번호(이어 치면 두 자리), Tab = 팀 바꾸기, Backspace = 되돌리기
  - 점수 · 서브권 · 우리 로테는 저절로. 두 팀에서 같은 랠리 끝을 같이 눌러도 점수는 한 번(공격 득점↔디그 실패, 막힘↔블로킹 득점, 에이스↔리시브 0)
  - 3연속 실점·득점 표시, 세트 끝나면 "다음 세트 시작", 인터넷이 끊겨도 폰에 남았다가 올라감("대기 N")
- 결과(모두 봄, Supabase Realtime으로 다른 사람 기록이 바로 들어옴 — `live_rallies`·`live_games`를 `supabase_realtime` 발행에 넣음, 끊기면 6초마다 다시 불러옴. 두 사람이 팀을 나눠 같이 입력해도 됨, 이번 세트 / 경기 전체): 사이드아웃 % · 브레이크 % · 공격 효율(SNU · 상대) · 리시브 평균(SNU · 상대), 두 팀 득점 구성, 팀마다 선수별 표(서브 에이스/범실 · 리시브 평균 · 공격 득점/시도 · 범실 · 막힘 · 효율 · 블로킹 득점/유효 · 디그 성공/시도 · 파울 · 득점), 팀마다 공격 종류별(분배 · 득점 · 범실·막힘 · 효율) + 득점 자리 코트 지도(묶음별 색: 레프트 · 라이트 · A·B·이동 · 앞차·백차 · 파이프·백어택 · 그 외, 팁은 속 빈 원 · 구역 수 · 팁 수 · 범실 중 토스 미스 수), 점수 상황별(SNU 사이드아웃 · 브레이크 · 공격 효율), 로테별(SNU)
- DB: `live_games`(ref_kind·ref_id = 대회/교류전/scout, label, team(분석 팀, 비면 SNU), opponent, roster({us,opp: [{no,pos}]}), sets = 세트별 첫 서브·로테) · `live_rallies` 한 줄 = 플레이 하나(side us/opp, kind srv·rcv·atk·blk·dig·err, res, player_id(SNU) · opp_no(상대), atype(lo·lq·ro·rq·a·b·mv·fc·bc·pipe·back·etc, 예전 w4·o2·q3), shot(spike·tip), miss(atk·set), x · y · zone, point, rot, serve). 읽기 부원, 쓰기 전력분석 담당·관리자

## 6-1. 교내 대회
- 1학기 총장배, 2학기 종합체육대회. 공지·참가 신청은 스포츠진흥원 네이버 카페(대회마다 글 주소 저장)
- 대회 기간에는 남·여 정규 훈련 대신 "종합체육대회 주"(달력·홈에 표시, 피지컬은 고르는 날)
- 가능일: 부원(남녀)이 날마다 참/불참(불참은 사유 · 메모, 대회·훈련 투표와 같은 창) → 일정 담당(부주장)·관리자가 경기마다 심판 배정
- 심판 칸은 남녀 명단(서버 함수 `cup_people()`, 이름·팀만)에서 고르거나 직접 입력. 그날 가능한 사람을 누르면 빈 칸에 들어가고, 숫자는 이번 대회에 맡은 횟수
- 대진표: 자리 이름 "A1위"(조 경기가 다 끝나면) · "6강 1경기 승자/패자"(그 경기 점수가 들어가면)가 팀으로 바뀌고, 이 이름으로 선이 이어짐. 점수는 "2-1"처럼 세트
- 경기 목록: 시간 · 경기 이름 · 점수 / 팀 · 버튼(심판 · 사진 · 기록 · 수정). 심판은 "심판" 버튼을 눌러야 펼쳐짐(내가 맡은 경기는 버튼에 "내 주심" 등으로 표시)
- 경기 수정 창: 예선 경기는 A·B 팀을 고르고, 본선 경기는 자리 이름(A1위 · B선택 · 6강 1경기 승자)만 — 팀 선택 칸 없음, 팀은 결과대로 저절로 들어감
- 화면은 경기 · 가능일 · 조편성 · 대진표 탭으로 나눔
- 자동 맞춤(`syncCup`): 팀 추가·수정·삭제, 조 추첨, 대회 수정(본선 진출 조 n위) 때 조마다 풀리그 경기와 본선 대진을 다시 계산. 같은 경기는 시간·심판·점수를 그대로 두고, 빠진 경기는 추가(날짜는 대회 첫날/마지막 날, 시간은 비워 둠), 필요 없어진 경기는 점수가 없을 때만 삭제
- 본선: 조 n위까지 자리 수에 맞춰 부전승(1위 먼저)을 두고 첫 경기 같은 조끼리는 피함. 3개 조 · 2위까지는 우리 대회 방식(A1위·C1위 부전승, B선택). 2개 조 → 4강(A1–B2, B1–A2), 4개 조 → 8강. 본선 9팀 이상은 직접 입력
- 경기 기록: 경기마다 "기록" → 세트별 점수(3세트는 15점) 또는 기권. 세트 수·승자는 자동 계산(`cup_score()`), 그 경기 주심·부심·기록심과 관리자·주장·부주장만 입력
- 기권: 기권 팀은 조 순위에서 빠지고(그 팀과 한 경기도 순위 계산에서 뺌) "A1위" 같은 본선 자리는 그 아래 순위 팀이 올라감
- 자리 선택("B선택", `cups.picks`): B조 경기가 끝나면 1위가 들어갈 경기를 관리자가 골라 줌(대진표 탭, 대진표 아래 한 줄). 1위는 고른 경기, 2위는 남은 자리
- 본선 기권(`cup_teams.ko_out`): 예선 기록·순위는 그대로 두고 본선 자리만 다음 순위 팀이 진출 (예: 2026 종체 화학부 배구부 → CSDP)
- 팀 사진: 경기마다 "사진" → 팀별로 휴대폰 사진 올리기(부원 누구나, 1600px로 줄여 비공개 버킷 `cup-photos`, 표 `cup_photos`). 결과 글에는 경기마다 1장: 이긴 팀 먼저, 그다음 아직 사진이 안 들어간 팀(같은 팀은 한 번만). 붙여 넣을 때 사진이 안 따라오면 아래 사진을 저장해서 올림
- 오늘 공지(카톡·카페): "오늘은 B조 예선 경기가 있는 날입니다." + 그날 경기 + 대회 공지 문구(`cups.notice`, 한 줄에 하나 → "* …") + "B조 대표자분들과 본선에 진출하게 된 팀 대표자는 위 사항들을 팀원에게 전달 부탁드리겠습니다."
- 카페 일정 글에는 주심·부심만 (선심·기록심은 뺌)
- 카페 글: 교내 대회 화면 "카페 글" → 경기 결과(날짜별, 카페에 올리던 모양: "A조 1경기 / 팀 VS 팀 / 1세트 21:12 … / 팀 2:0 승리", 팀이 2개뿐인 조는 "C조 예선 순위 결정전", 그날 끝난 조는 "조별 최종 순위", 끝에 "수고하셨습니다." · 팀 사진 자리 표시 켜고 끄기) / 경기 일정·심판 / 예선 결과·본선 대진 / 최종 결과 글을 만들어 제목·본문 복사(표 포함) → 카페 글쓰기에 붙여 넣기. 카페 자동 올리기는 네이버 개발자 앱·로그인 연결이 필요해 아직 안 함
- 요강·공지에 있는 계좌번호·전화번호는 저장하지 않음

## 6-2. 전력분석 (`court.js`)
- 두 갈래: 영상 분석(아래, 예전 프로그램) / 실시간 경기 분석(6-0)
- 시작 로테 · 로테별 득실 모아 보기: 엑셀에 "Start Rotation"(경기 · 세트 · 팀마다 시작 로테 R, 자리 1~6 등번호·포지션, 리베로, 첫 서브) · "Rotation"(팀 · 로테마다 사이드아웃 · 브레이크 · 득실) 시트, 목록 "팀별" 탭에 그 팀의 시작 로테 표(R별 횟수) · 로테별 득실(누적)
- 분석 팀은 SNU가 아니어도 됨: Match Setup의 "분석 팀"(비우거나 SNU면 SNU). 다른 팀이면 Edit Lineup에서 두 팀 다 등번호 · 포지션 · 리베로 번호, 기록은 `opp_no`, 화면·엑셀의 팀 이름도 그 팀으로. 시즌 탭은 SNU 경기만, "팀별" 탭(예전 상대 탭)은 그 팀이 분석 팀이든 상대든 모아 봄. 라인업·기록이 있으면 SNU ↔ 다른 팀은 못 바꿈
예전 전력분석 담당이 쓰던 PC 프로그램(VolleyballLogger, Kivy · SNU.py) 기능을 그대로 옮기고 화면만 정리. 원래 프로그램에 없던 것 중 남긴 것: 선수가 로테대로 실제 자리로 움직이는 코트, 리베로 자동 교대·교체 기록(요청), 영상(유튜브·치지직), 분석 탭(기록지 · 로테이션별 득실) · 목록 화면의 시즌·상대 탭.
- Match Setup(`+ 경기`): 대회명(`title`) · 스테이지(`stage`) · 분석 팀(`team`) · 상대 팀 · 날짜 · 기록자(`recorder`) · 인원 6인제/9인제(`division`, 다른 칸과 같은 선택 칸) · 유튜브 · 치지직 → "다음: 라인업"으로 바로 Edit Lineup
- Edit Lineup: 분석 팀이 SNU이고 라인업이 비어 있으면 가장 가까운 대회·교류전 주전(→ 엔트리 → 나머지 부원)을 명단 포지션으로 자동 배치(1 S · 2 OH · 3 MB · 4 OP · 5 OH · 6 MB = R1, 리베로 L 두 명까지) → 고쳐서 저장
- Edit Lineup(`scout_matches.lineup`): 6인제는 SNU 6명(라인업 용지처럼 앞줄 4·3·2 / 뒷줄 5·6·1, 자리별 포지션 OH·MB·OP·S) · 리베로 1·2, 상대 등번호 6개 + 포지션 · 리베로 1·2, 세트 시작 로테·첫 서브. 9인제는 자리 고정 C·S / L·FS·BS·R / LB·CB·RB(로테·리베로 없음), 첫 서브
- 기록 화면: 점수 · Set · Rot(우리:상대) · Rally, 버튼 Undo · Settings · Change Court · Edit Lineup · Export Excel · RESET
  - 선수를 누르면 Serve·Receive·Attack·Set·Block·Dig·Pass·Fault & Error(4+4) → 결과 → 세부(범실 이유). "‹ 뒤로"로 한 단계 뒤로
  - 동작 — 이름·순서는 예전 프로그램 그대로: Serve(Ace · 1/2/3-serve · Serve Error(Net·Out) · Foot Fault) · Receive(Receive Error · Over Pass (Play) · 1/2/3-Receive) · Attack(Spike/Tip/Dump/Down Ball/Over Pass Kill · Hit In Play · Spike/Tip/Dump/Down Ball Error(Into Net·Blocked·Out) · Back Row Fault) · Set(1/2/3-Set (In)·(Out) · Set Error) · Block(Block · Block Assist · Block In Play · half block · Block Error(Into Net·Out)) · Dig(Tip/Dump/Down Ball/Spike/block Dig · 각 Error) · Pass(F.B. Return In Play · Over Pass In Play · 1/2/3-Free Ball Pass) · Fault & Error(???? · Ball Handling · Net Fault · Under Net · Over Net · Whose Ball? · Ball Return Err · Free Ball Recv Err · Out of Rotation · Outside Court). 숫자는 3이 가장 좋음. 공격 범실 이유 Blocked는 "막힘"으로 셈. 서브·공격은 코스(선택)
  - 득점·실점이면 점수·서브권·로테(6인제, 우리·상대)·Rally가 자동. 한 랠리에 점수는 한 번만(예: 서브 Ace 뒤 Block을 눌러도 1점)
  - Settings(예전 Game Settings): Set · Our Rot · Opp Rot · Serving · Rally를 언제든 맞춤(기록으로 남아 Undo 가능, `action = 'cfg'`)
  - RESET: 이 세트 기록 모두 지우기(확인 후), 선수는 그대로
  - Undo: 마지막 기록 지우고 세트를 처음부터 다시 따라가 점수·로테를 맞춤
  - 코트 버튼: 등번호 · 이름 · 자리 번호(왼쪽 위) · 포지션(오른쪽 위, 리베로 L)
  - 컴퓨터: 방향키로 선수 이동 · Enter로 기록 · 숫자 키 1~9로 바로 고르기 · Backspace(창에선 한 단계 뒤로, 코트에선 Undo)
  - 저장은 화면에 먼저 넣고 서버로 차례대로 보냄(체육관 인터넷이 끊겨도 폰에 남았다가 연결되면 올림, "대기 N")
  - 리베로 (우리·상대 둘 다): 라인업 포지션이 MB인 자리가 뒷줄(5·6번)에 오면 그 자리에 리베로(우리 초록 · 상대 주황, L)가 자동으로 섬. 1번 자리 MB는 그 팀 서브 차례면 직접 서브하고, 서브권을 잃으면 바로 리베로로. 앞줄로 가면 MB가 돌아옴 → 코트에 리베로는 늘 한 명. 상대도 라인업에 포지션(MB)과 리베로 번호를 넣어야 자동. 리베로로 뛰는 선수를 누르면 Serve·Attack·Block 없이 나머지 동작만
  - 명단에 L로 넣은 선수도 언제든 다른 포지션(OH 등)으로 투입 가능: 선발 6명에 넣거나, 경기 중 "교체"로 들어감(예: 수비 약한 OH 대신 L 선수). 들어올 선수 목록에 L 선수도 나오고(· L 표시), 교체 창 "들어옴"에서 고르고 포지션(OH 등)을 정함. 일반 선수로 들어가면 모든 동작(서브 포함) 기록, 리베로 자리는 다른 리베로가 맡고(없으면 리베로 없이) 리베로 줄에서 빠짐. 선발 6명과 리베로 칸에 같은 사람을 같이 넣을 순 없음
  - 교체: 코트 아래 "교체"(우리·상대 따로) 또는 벤치·안 뛰는 리베로를 누르면 교체 창 → 나감(코트 6명, 자리·포지션) · 들어옴(우리는 벤치·리베로, 상대는 번호) · 포지션(나간 선수 포지션으로 미리 골라 둠) → "교체". 리베로가 2명이면 같은 창 위쪽 "코트 리베로"에서 바꿈. 이후 코트·로테·리베로 자동에 반영(`skill = 'sub'`, kind = 포지션, 분석 숫자엔 안 들어감)
- Export Excel(예전 프로그램과 같은 파일): 파일 이름 `날짜_대회명_스테이지_SNU vs 상대.xlsx`, 시트 Logs(Division · Date · Timestamp · Tournament · Stage · Set Number · Rotation(득점 뒤 우리:상대) · Rally Count · Serving Team · Player No · Player Name · Position · Category · Action · Action Type · Detail · Score · Point To · Did Rotate · Recorder) + 팀별 기록지 시트 SNU · 상대(배번 · 선수명 · 득점 · 공격 · 공격 성공률 · 공격 효율 · 공격 점유율 · 서브 · 서브 점수 · 블로킹 · 디그 · 리시브 · 리시브 점수 · 세트 · 세트 점수 · 범실, 성공률 25% 이상 노랑 · 효율 + 초록 / − 빨강 · 0은 "-"). ExcelJS(cdnjs) 사용. 목록 화면 엑셀은 전체 경기 Logs + SNU 기록지
- 분석 탭: 같은 기록지(SNU · 상대) + 로테이션별 득실(6인제)
- 영상: 유튜브(앱 안에서 재생 · 기록마다 영상 시간 자동) 또는 치지직 다시보기(앱 안에 안 열려서 "치지직" 버튼으로 따로 열기, `naver.me` 공유 주소는 Edge Function `resolve-link`가 풀어 줌). 영상 시간 칸 + "시계 시작"(±5초)으로 기록마다 시간이 붙음
- DB: `scout_events`(action · detail · kind(교체 포지션) · zone(교체 자리) · rot · opp_rot · rally · serve · point · score), 점수가 난 랠리는 `scout_points`(6인제만, 로테이션별 득실용)

## 7. 고칠 때

1. 파일을 고치고 `index.html`의 `?v=` 숫자를 올려요 (휴대폰 캐시 갱신).
2. `main`에 push 하면 1분 안에 배포돼요.
3. DB를 바꿀 때:
   - Supabase 마이그레이션으로 적용해요.
   - `supabase/schema.sql`의 해당 부분도 같이 고쳐요.
   - 이 문서의 4절(표)과 3절(권한)도 맞춰요.
4. 서버 함수를 바꾸면 `supabase/functions/<이름>/index.ts`도 같이 올려요.

## 8. 지켜야 할 것

- **비밀값은 코드에 두지 않기**
  - service_role 키는 클라이언트 파일에 절대 넣지 않아요.
  - 알림 키와 `x-cron` 값은 서버에서 만들어 vault에만 둬요.
- 일부 공개 유튜브 재생목록 주소는 DB(`videos`)에만 두고, 코드나 문서에 적지 않아요.
- DB 표·열을 지우는 변경(DROP)은 미리 확인받고 해요.

## 9. 디자인 원칙

- 목록의 항목(대회, 일정, 지역, 영상 등)은 하나씩 **박스(칸)로 나눠** 보여 줘요. 새 화면도 이걸 기본으로 해요 (`index.html`의 `.boxes`, `.box-cols`).
